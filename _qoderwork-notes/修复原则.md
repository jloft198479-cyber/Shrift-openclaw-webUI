# 修复原则

> 所有代码修复必须遵守的底线原则。违反即返工。

## 安装路径是唯一真相源

安装流程生成什么，卸载流程就清除什么。配置的生命周期严格绑定安装/卸载路径。

## 通用性优先

虾指挥是面向 GitHub 公开发布的产品，服务于所有用户。任何修复必须是通用解法，不能为了兼容某一套存量配置而扭曲正常逻辑。

判断标准：如果你的修复里出现了针对特定 Agent、特定技能、特定目录名的 if-else，那就是个性化适配，不是修复。

## 存量差异靠数据迁移，不靠改代码

修复后 `syncAllRosters()` 会自动将磁盘状态对齐到正确逻辑。如果存量数据与正确逻辑不一致（比如某 Agent 没有 skills 配置却有 junction），那是数据层面的事——不需要在代码里加特殊分支去兼容。

## 硬编码是红线

为了贴合某个特定配置而写特殊分支 = 硬编码。不管看起来多"无害"，都是技术债。
